# Smart Add v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1 of `smart-add.js`: a "Suggested" section in Spotify's Add to playlist modal driven by manual artist/show → playlist mappings, then publish the repo so people can install it from the Spicetify Marketplace.

**Architecture:** One IIFE in `smart-add.js`, organized by the existing `//#region` blocks. Pure logic (parsing, grouping, pruning, freshness) is exported through a `module.exports` guard and unit-tested with `node --test`, following `spicetify-local-files-plus`. Everything that touches Spotify (trigger capture, modal injection, menus, modals) is verified live over CDP with the `spicetify-live-test` skill against `tests.live.md`.

**Tech Stack:** Plain JS (no build), Spicetify Platform APIs (`PlaylistAPI`, `RootlistAPI`, `GraphQL`, `ContextMenu`, `Menu`, `PopupModal`, `LocalStorage`), `node:test`, pnpm, husky, commitlint, release-please.

**Spec:** `docs/superpowers/specs/2026-10-11-smart-add-design.md` (read the Spike results section before Task 4 or 5).

## Global Constraints

- Single file `smart-add.js`, no runtime dependencies, no bundler. New code goes in the matching `//#region`.
- `SA_` constant prefix; `sa-` CSS class and DOM id prefix; JSDoc on every function.
- Log prefix `[Smart Add]` (already `SA_LOG`).
- Persistence is `Spicetify.LocalStorage` only: `smart-add-data`, `smart-add-config`; corrupt data is copied to `smart-add-data-backup` before falling back to defaults.
- Config defaults `{ enabled: true, maxPerGroup: 5, showGroupHeaders: true }`.
- Mappings keyed by artist/show URI; `name` is a display cache. Playlist names resolve at render time from the rootlist.
- Modal anchor: a `form` containing both `input[role=searchbox]` and `ul[role=menu]`. Never match on text or hashed classes. The `#context-menu` legacy submenu is out of scope and must stay untouched.
- Inject only if the trigger capture is at most 2000 ms old when the form appears, and sources resolve within 300 ms of the form appearing. Otherwise render nothing.
- At most 3 groups; at most `maxPerGroup` rows per group.
- Click adds instantly via `PlaylistAPI.add(playlistUri, missingUris, { after: 'end' })` and shows `Spicetify.showNotification('Added to <name>')`. No Undo.
- Every injector/render path is in try/catch; on failure the native modal must still work.
- CSS uses Spicetify theme variables only, no hardcoded colors.
- Conventional Commits; never hand-bump versions or edit `CHANGELOG.md`.
- After each edit: copy `smart-add.js` to `%APPDATA%\spicetify\Extensions\` and `%APPDATA%\Spotify\Apps\xpui\extensions\`, reload via CDP (no symlinks).

## Review Focus

1. **Virtualized list:** a mapped playlist that already holds the track but whose native row is not rendered shows as unsaved. Clicking it must not add a duplicate; it should flip to ✓ with "Already in <name>". (Task 5, click-path test.)
2. **Native Done after our add (spec #1b, skipped in the spike):** the native row for a playlist we just added to still says unchecked. Ticking it and pressing Done would duplicate. The native twin must be blocked for that modal instance. (Task 5, T3b.)
3. **Stale capture:** the user clicks a row "+" then cancels, and within 2 s opens the modal from somewhere we do not capture. Suggestions for the old track would be wrong. Captures are consumed by the first form that uses them. (Task 4 unit test + Task 5.)
4. **Rootlist failure wipes mappings:** a transient `RootlistAPI` failure returns no playlists, and pruning would delete every mapping. Pruning bails when the valid set is empty. (Task 3 unit test.)
5. **Bad import file:** importing malformed JSON or a file from another extension must leave current data unchanged and show an error toast. (Task 7 unit test.)

- Produces:

  - `saGetPlaylists({ force?: boolean }) -> Promise<Array<{uri, name}>>`: 30 s cache + in-flight dedupe (pattern `enhanced-folders.js` `fetchFolderMap`). On error returns last cache or `[]`.
  - `saTrackArtists(trackUnion) -> Source[]` where `Source = { uri: string, name: string, kind: 'artist'|'show' }`: primary artist first, then the rest, deduped by URI.

Episode → `Definitions.queryNpvEpisode({ uri })` → `data.episodeUnionV2.podcastV2.data.{uri,name}` as one `show` source. Union across URIs in input order, deduped. Failed URIs contribute nothing.
  - `saSourcesFromPlayerItem(item) -> Source[]`: from `Spicetify.Player.data.item` (`artists[].uri/name` for tracks; `show.uri/name` or empty for episodes, then fall back to `saResolveSources`).

### Task 5: Modal injector and styles

**Files:**
- Modify: `smart-add.js` (Modal Injector, Styles, Bootstrap regions; export `saPlaylistUriFromLabelledBy`)
- Create: `test/injector.test.js`

**Interfaces:**
- Consumes: `saIsFresh`, `saCapture` (Task 4); `buildSuggestionGroups`, `saPruneMappings` (Task 3); `saGetPlaylists` (Task 2); `saConfig`.
- Produces:
  - `saPlaylistUriFromLabelledBy(attr: string|null) -> string|null`: `'listrow-title-spotify:playlist:abc'` → `'spotify:playlist:abc'`; anything else → `null`.
  - `saInstallInjector()`: body `MutationObserver` (childList, subtree). For each matching form not yet handled (track handled forms in a `WeakSet`), run `saInjectInto(form)`; if our `#sa-suggested` was removed from a handled form, re-insert the same node.
  - `saInjectInto(form)`: if `!saConfig.enabled` or `!saIsFresh(saCapture, now)` → return. Mark capture `used`. Race `capture.sources` against 300 ms; on timeout or empty → return. Get playlists, prune (save if `removed > 0`), read `savedInSet` from `button[role=menuitemcheckbox][aria-checked=true]` via `saPlaylistUriFromLabelledBy`, build groups; empty → return. Render and `form.insertBefore(section, ul)`.
  - `saInjectStyles()`: one `<style id="sa-styles">`.

Render rules:
- Section `<section id="sa-suggested">`. With `showGroupHeaders`, each group gets a header `Suggested · <source.name>`; without it, one `Suggested` header and the rows flattened in group order.
- Rows are `<button type="button" class="sa-row">` (type=button so the form never submits) showing the playlist name; saved rows show ✓ and are `disabled`.
- Click: disable the row, `PlaylistAPI.getContents(playlistUri)` to get existing URIs, `missing = capture.uris` not already present. If `missing` is empty → ✓ + toast `Already in <name>`. Else `PlaylistAPI.add(playlistUri, missing, { after: 'end' })` → ✓ + toast `Added to <name>`. On error → re-enable, toast `Couldn't add to <name>` with `isError: true`, log.
- After a successful add, block the native twin for this form: add the URI to a per-form set, add a rule to a `<style>` inside our section that dims `form button[aria-labelledby="listrow-title-<uri>"]` and sets `pointer-events: none`, and swallow `click`/`keydown` (Enter, Space) on those buttons with a capture-phase listener on the form.
- Search: listen for `input` on the form's searchbox; set `section.hidden = searchbox.value !== ''`.
- Styling: reuse the native row text class read from the first native row's title element where possible; layout and colors via Spicetify variables (`--spice-text`, `--spice-subtext`, `--spice-card`, `--spice-button`).
- Every function body above is wrapped in try/catch logging `[Smart Add] inject failed` and leaving the form untouched. If re-insertion throws, stop re-injecting for that form.
